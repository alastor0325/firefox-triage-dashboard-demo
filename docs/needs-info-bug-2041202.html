Bug description (excerpt)

Macbook Pro with macOS Tahoe, newest version. Audio interface connected via USB. Navigate to Youtube and start a video playback. Hit stop button - a short audio buffer remains playing creating a buzzing/beeping sound. Hit play again and audio continues playing. The problem also occurs when skimming the audio with a mouse using the browser window progress slider. Same happens on other webpages also where audio playback is stopped e.g. when scrolling a Facebook content feed where audio is turned on on video clips. Comparison: Audacity YES, Firefox YES, Chrome NO, Safari NO, Apple Music NO. Reporter suspects audio playback tear down issue / protocol change introduced in macOS Tahoe.

Thanks for the detailed report and the cross-browser comparison. The fact that Firefox and Audacity both reproduce the issue while Chrome, Safari, and Apple Music do not is a useful signal — Firefox uses cubeb / CoreAudio for audio output on macOS, and Audacity likewise talks to lower-level audio APIs, so this may be a cubeb / CoreAudio interaction specific to macOS Tahoe or to the connected USB audio interface.

To investigate, we need a bit more data:

  • Could you attach about:support (Help > More troubleshooting information > Copy text to clipboard)?
  • Does the issue still happen in a Private Browsing window (Cmd+Shift+P)? This rules out extensions.
  • Does it reproduce when the USB audio interface is not connected (using the MacBook's built-in speakers/headphone jack)? This helps narrow whether the trigger is the external device.
  • Could you share the exact model/name of the USB audio interface and its sample-rate / buffer settings (if configurable)?

Please capture a media log: please follow the instruction video to capture one using about:logging with the "media" preset. After reproducing the buzzing sound, save the log file and attach it here.
