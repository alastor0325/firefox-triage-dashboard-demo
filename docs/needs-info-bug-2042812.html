Thanks for the report and the screenshot — the YouTube stats overlay confirms this is VP9 1440p24 (vp09.00.51.08.01.01.01.01.00) with Opus audio, and the corruption pattern looks like macroblock / reference-frame desync rather than a rendering glitch.

To narrow down whether this comes from the hardware decode path or the software (ffvpx) path, could you help with a few things:

  • Please paste the full contents of about:support from both Windows 11 and macOS 26.5 (especially the Graphics, Media, and Important Modified Preferences sections).
  • Does the corruption still reproduce in Private Browsing mode? (rules out extensions)
  • Please try toggling media.hardware-video-decoding.enabled to false in about:config, then fully quit and restart Firefox (not just close the window), and replay https://www.youtube.com/watch?v=sEymyO5Abp4. Does the corruption still happen?
  • Does it also reproduce at lower resolutions on the same video (720p, 1080p)? You can force a resolution from the YouTube settings gear.
  • Does it reproduce on other VP9 1440p videos, or only this one?

If the issue still persists after the HW-decode-off test, please capture a media log: follow the instruction video to capture one using about:logging with the "media" preset. After reproducing the issue, save the log file and attach it here. If you have any privacy concerns about sharing the log publicly, please email it to media-alerts@mozilla.com instead.
