Thanks for the report, Jake. This is the same issue as bug 1711812 (yuv420p10 (10-bit) H.264 fails to play), which is already being investigated by :bwerth.

The underlying limitation is that the platform H.264 decoders on Windows (Media Foundation) and macOS (VideoToolbox) do not support the 10-bit (High 10 / yuv420p10) profile — they only support 8-bit. On Windows specifically, our DXVA path explicitly requires ColorDepth::COLOR_8 for H.264, and the WMF software H.264 MFT also doesn't produce a usable 10-bit output. Edge can play this because Microsoft Edge has additional codec support beyond what's exposed through the public Media Foundation H.264 MFT. macOS appears to work for you, but on other reporters' macOS systems the bottom of the frame glitches (bug 1743824) — VideoToolbox technically accepts the stream but doesn't decode it cleanly.

Closing this as a duplicate of bug 1711812 so all the discussion stays in one place. Please follow that bug for updates.
